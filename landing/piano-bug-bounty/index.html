03 Pod kapotou

Vypadá jednoduše. Uvnitř je to pořádný stroj.

Jak je Hugo postavený a jak ho vyvíjíme — trochu techničtěji, ale pořád bez tajných detailů.

iOS + Android
Jedna Flutter / Dart codebase pro obě platformy, s nativním hlasovým mostem (Swift / Kotlin) pro streamování audia. Offline-first (šifrovaný).
Backend (BE)
Node.js 22 + Express, jediný zapisovatel do DB. PostgreSQL 18 přes Prisma ORM (~85 modelů). Real-time sync kasy přes WebSockety.
Web Admin (FE)
React 19 + Vite, Tailwind v4, react-router. SPA komunikuje s BE přes REST + WS. 17 jazyků (i18next), výchozí čeština.
Monorepo
Jedno úložiště, čtyři produkční služby (API, Admin, Landing, POS) + sdílené balíčky. Sazby DPH a jednotky jsou byte-identické kopie napříč službami, aby kasa a účtárna počítaly totožně.
Peníze
Jediný zdroj pravdy — jeden modul počítá DPH i součty v celočíselných jednotkách; POS je bit-for-bit zrcadlo backendu (pinnuté golden fixture). Žádná „ztracená koruna“ v přiznání.
— A takhle to vyvíjíme —

Adversariální AI review

Než se kód mergne, orchestruje ho Claude a pod ním se v loopu klidně desítek agentů hádají další Claude a Codex — jeden píše, druhý trhá návrh na kusy. Točí se to tak dlouho, dokud se neshodnou.

Self-healing triage

Tvůj report → Claude ho zanalyzuje izolovaně (čte ho jen jako data) → oddělený „broker“ bez přístupu k AI výstup ověří a založí Jira ticket. Oprava pak projde review vývojářů.

A tvůj report to spouští

Stage → produkce

Každá změna nejdřív přistane na stagingu (push do main). Do produkce se pustí až vytvořením GitHub Release — ostrá data nikdy nedostanou neověřenou verzi.
